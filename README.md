# Rangefinder

**Anonymous, athlete-contributed benchmarks of what NIL deals actually pay.**

College athletes share the terms of a deal they signed and, in return, see what comparable athletes were paid. Agents, brands, collectives and athletic departments subscribe. Why this niche, and what was rejected: [docs/RESEARCH.md](docs/RESEARCH.md).

## How it works

- **Give to get.** An athlete who shares one deal gets full access for 12 months. Everyone else pays: Pro $299/month, Team $1,499/month (edit in `server/plans.js`).
- **Anonymous by construction.** There are no fields for name, school, team or brand. No statistic or list is shown for fewer than five deals; the 10th and 90th percentiles need ten. Individual deals are shown with rounded amounts and follower ranges only.
- **Benchmarks.** Percentile bands by sport, level, follower range, deal type, payer, industry, class year, region and quarter, plus the share of deals NIL Go cleared.
- **Range finder.** Describe an athlete and a deal; it finds the tightest group of comparable deals, widening one attribute at a time and recording what it relaxed, then shows where a proposed amount sits. The result prints as a comp report.
- **Quality control.** Every submission is screened; implausible ones wait in a moderator queue. Moderators can approve, reject, or mark a deal verified.
- **API** with keys and daily quotas, CSV export, and Stripe subscriptions.

## Run it

Requires Node 22.13+. No database server, no native modules.

```bash
npm install
npm run build        # builds the web app into web/dist
npm start            # http://localhost:8080
```

The database starts **empty**, and the site says so. To see the product with data in it:

```bash
npm run demo:seed    # 1,500 synthetic deals; the site shows a "Sample data" banner
npm run demo:purge   # remove them
```

Demo deals are generated by formulas in `server/demo.js`. They are not real and must be purged before real users arrive.

Other commands: `npm test`, `npm run dev`, `npm run web:dev`. Configuration is by environment variable — see [.env.example](.env.example). Set `ADMIN_EMAILS` to the accounts that should moderate.

## Taking payments

1. In Stripe, create two recurring monthly prices (Pro, Team).
2. Set `STRIPE_SECRET_KEY`, `STRIPE_PRICE_PRO`, `STRIPE_PRICE_TEAM` and `PUBLIC_URL`.
3. Add a webhook at `<PUBLIC_URL>/api/billing/webhook` for `checkout.session.completed`, `customer.subscription.updated` and `customer.subscription.deleted`; set its signing secret as `STRIPE_WEBHOOK_SECRET`.

Without these the pricing page shows a contact link (`SALES_EMAIL`). To set a plan by hand: `UPDATE users SET plan = 'pro' WHERE email = '…'`.

## Layout

```
server/
  domain.js       the fields of a deal and their validation
  benchmarks.js   percentiles, suppression, cohort search, anonymisation, screening
  deals.js        storage, contributor access, moderation
  plans.js        access tiers
  demo.js         synthetic sample data
  auth.js billing.js app.js index.js
web/              React + Vite front end
test/             node:test suites
docs/RESEARCH.md  niche research
```

The API is documented in the app at `/docs`.

## Before launch

- **Seed the database.** Nothing is worth selling until real athletes contribute. Plan how the first few hundred deals arrive.
- **Legal review.** Confidentiality clauses in NIL contracts, the Terms and Privacy drafts in `web/src/pages/Legal.jsx`, and state NIL laws.
- **Verification.** Today a moderator marks deals verified by hand; there is no proof upload.
- **Accounts.** Add email verification and a forgotten-password flow (needs an email provider).
- SQLite on one node is fine to launch; move to Postgres for more than one instance.
